## Question 1

A clinic app stores a `Patient` record in variable `original`. Another method receives `copy = original` and changes the patient's phone number through `copy`. The reception desk sees the new number when reading `original`. Explain why both variables reflect the same change and what kind of type behavior this is.

## Question 2

## Question 3

## Answers

### Question 1

Class instances are reference types: `copy` and `original` refer to the same object on the heap. Mutating through either alias changes the single instance (ch.01 instance vs reference).

### Question 2

Type: fields (SKU, quantity) and methods (`AdjustStock`). Orchestrator: coordinates multiple pallets, persistence, validation across pallets — HasA relationships (ch.01 fields/methods, ch.05 IsA vs HasA).

### Question 3

Constructors enforce invariants at birth (non-negative balance, required account number). Post-construction assignment can leave invalid states temporarily and skips centralized validation (ch.03 why constructors needed, parameterized constructor).

### Question 4

Property with private backing field validates in setter; callers use property syntax. Encapsulation allows later changing storage (e.g., cents int) without changing public API. Simple getters can use expression-bodied form (`=>`) when read-only (ch.02 full properties, expression-bodied properties, ch.07 encapsulation).

### Question 5

Indexer `this[int index]` with get/set; throw `IndexOutOfRangeException` or return null per API contract when invalid (ch.02 indexers, indexer real-world example).

### Question 6

Constructor chaining `: this(id, name)` from the three-parameter constructor; optional parameter or overload calls two-parameter constructor (ch.03 constructor chaining, method overloading).

### Question 7

Copy constructor `LineItem(LineItem other)` copying scalars into new instance; for deeper graphs, clone nested objects too (ch.03 copy constructor pattern).

### Question 8

Static constructor on the fee calculator type loads rates once before first static or instance use of that type. Contrast: instance finalizers run nondeterministically at GC — not for one-time setup (ch.03 static constructor, destructor preview, ch.04 static fields).

### Question 9

Private constructor prevents external `new`; static property `Instance` returns lazy static field; single shared object (ch.03 private constructor, ch.04 singleton preview).

### Question 10

Driver is not a Vehicle — no IsA. Route HasA driver and HasA vehicle (composition). Inheritance would violate domain model (ch.05 IsA vs HasA, generalization/specialization).

### Question 11

Base reference in loop; each element's virtual `CalculatePay()` resolved at runtime to derived implementation (ch.05 runtime polymorphism, virtual/override).

### Question 12

Subclass used `new` to hide base method; static type of reference determines call. Override requires `virtual`/`override` for polymorphism (ch.05 method hiding vs overriding).

### Question 13

Abstract base when shared fields/default logging behavior needed; interface when unrelated types must share contract only (ch.06 abstract class vs interface, application development).

### Question 14

Yes — class `: IExportable, ISearchable`. One object implements both contracts; callers cast or use interface-typed references (ch.06 multiple interfaces).

### Question 15

Explicit interface implementation: `string IExportable.Name => ...` vs `string IStorageItem.Name => ...` (ch.06 explicit interface implementation).

### Question 16

`protected` visible to subclasses only, not unrelated types like `ReportPrinter`. `protected internal` would also allow same-assembly access; `private protected` limits to derived types **in the same assembly** only. Neither compound modifier helps an unrelated printer class (ch.07 access modifiers, encapsulation).

### Question 17

`monitor.ThresholdExceeded += Handler` on open; `-=` on close. Handlers keep publisher alive via delegate chain → memory leaks / ghost updates (ch.08 subscribe/unsubscribe, roles of events).

### Question 18

Custom class extending `EventArgs` with properties; event typed `EventHandler<ShipmentUpdatedEventArgs>` (ch.08 EventHandler&lt;T&gt;, custom EventArgs).

### Question 19

Operator overloading `public static Money operator +(Money a, Money b)`; throw or return error when currencies mismatch (ch.05 operator overloading).

### Question 20

Shared fields + default behavior in abstract base; abstract `RenderPreview()` forces derived implementation. Interface could work but abstract base reduces duplication for common state (ch.06 abstract methods, ch.09 abstract document example).

### Question 21

Enum restricts values, IntelliSense, type-safe switches; avoids magic numbers (ch.04 enums).

### Question 22

`MaxRetryCount` → `const` (compile-time literal). `ApiBaseUrl` → `static readonly` assigned in static constructor or field initializer at runtime (ch.04 const vs static readonly).

### Question 23

Override `Equals` and `GetHashCode` consistently; dictionaries/sets use hash codes — mismatched pair breaks lookups (ch.02 override Equals/GetHashCode).

### Question 24

Encapsulation → private balance + methods; Abstraction → payment interface/abstract processor; Inheritance → specialized accounts; Polymorphism → mixed list via base reference (ch.01 OOP overview preview, ch.09 capstone pillars).
