## Answers

### Question 1

Default thread is **foreground** (ch01). Process keeps running until worker prints — Main may exit first but process survives until worker completes. Set `IsBackground = true` if worker should not keep process alive.

### Question 2

Prints **less than 10000** (non-deterministic, often 7000–9900). **Race** on `total++` without synchronization (ch01 preview / ch06). Need `lock` or `Interlocked`.

### Question 3

**Yes**, worker keeps running after timed `Join` returns false (ch01). `IsAlive == true` means thread not yet terminated. Must `Join()` again or use cancellation for shutdown.

### Question 4

**Data race**: Main may read `results` before all callbacks write (ch02). Need `CountdownEvent`, `WaitHandle.WaitAll`, or join barrier before reading.

### Question 5

Console: **no deadlock** typically — no sync context to re-enter (ch04/ch05). **ASP.NET/UI**: blocking `.Result` while async continuation needs same context → **deadlock**.

### Question 6

**`AggregateException`** wrapping the `InvalidOperationException` (ch03). One inner exception from single faulted task; `Wait()` aggregates child faults.

### Question 7

Compiles. **`async void`**: exceptions after await not caught by caller's try/catch around `Run()` (ch04) — unobserved/crash path. Prefer `async Task`.

### Question 8

**No** — without passing `ct` into `Task.Delay(5000, ct)` or other cancellable API, method ignores caller token (ch04). Must cooperative check/pass token.

### Question 9

Missing **`Release()`** in `finally` after first `WaitAsync` (ch04 only-one). Semaphore count stays 0; second waiter blocks forever.

### Question 10

**Unreliable total** — data race on shared `decimal` (ch05). Use thread-local partial sums + merge or lock.

### Question 11

**At most 2** concurrent iterations (ch05 `MaxDegreeOfParallelism`), regardless of 16 cores.

### Question 12

Ordering may be **non-deterministic** across partitions unless **`AsOrdered()`** used (ch05 PLINQ). Merge phase still orders, but understanding pipeline order requires `AsOrdered()`.

### Question 13

External code can **`lock(account)`** too, causing unexpected contention/deadlock (ch06). Use **private dedicated sync root** inside `BankAccount`.

### Question 14

**Does not compile** — `Interlocked.Add` has no `decimal` overload (ch06). Use `lock` for decimal or convert strategy.

### Question 15

**LockRecursionException** / invalid — `ReaderWriterLockSlim` does not upgrade read→write on same thread by default (ch06). Exit read before write, or use `EnterUpgradeableReadLock`.

### Question 16

**Deadlock** (ch06) — circular wait on lockA and lockB. Fix with consistent lock ordering or single gate.

### Question 17

**Not thread-safe** — `Dictionary` concurrent writes throw or corrupt (ch07). Use `ConcurrentDictionary` or lock.

### Question 18

**GetOrAdd** factory may run twice; read-modify-write via indexer is **not atomic** (ch07). Use **`AddOrUpdate`** for surcharge atomically.

### Question 19

**Blocks** on 6th `Add` when bounded capacity 5 full and no consumer (ch07). Producer waits until space — backpressure by design.

### Question 20

**Yes** — `Validate(order3)` runs **synchronously on caller thread** before `await Task.WhenAll` (ch03). Only `t1`/`t2` on pool. For three parallel, wrap all three in `Task.Run` or use `Task.WhenAll` on three tasks.

### Question 21

Without **`volatile`**, CPU/compiler may cache `stop` in register — worker may loop forever (ch06 visibility). **`volatile`** ensures reads/writes are not reordered/cached unsafely for the flag.

### Question 22

**No** — cancel token passed to `Task.Run` only cancels **waiting to start**; once running, `Thread.Sleep` ignores token (ch03/ch04). Use `Task.Delay(..., ct)` or check `ct.ThrowIfCancellationRequested()` in loop.
