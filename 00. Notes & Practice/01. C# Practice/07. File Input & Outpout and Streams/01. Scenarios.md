## Answers

### Question 1
Check destination with `File.Exists` or compare hashes before copy; use `File.Copy(..., overwrite: false)` or skip when present. For repeated operations on the same archived file, wrap the path in `FileInfo` and reuse `Length`, `LastWriteTimeUtc`, and `CopyTo`/`MoveTo` instead of repeating static `File.*` calls — instance wrappers cache metadata for the same path.

### Question 2
Use `StreamReader` (or `File.ReadLines`) and read line-by-line in a `while ((line = reader.ReadLine()) != null)` loop so memory stays bounded. Keep a running `lineNumber` incremented each iteration; on parse failure, include that number in the error message and continue or abort per policy.

### Question 3
The writer and reader must use the same `Encoding` (e.g. both UTF-8 via matching `StreamWriter`/`StreamReader` constructors or explicit `Encoding.UTF8`). Mismatch (UTF-8 bytes read as system default) produces mojibake. Prefer UTF-8 with explicit constructors for new files.

### Question 4
Binary stores fixed-size numeric types compactly and avoids locale/parse issues. If read order does not mirror write order, subsequent reads misalign — `ReadString` after expecting an int reads garbage length prefixes, corrupting the rest of the file and often throwing `EndOfStreamException`.

### Question 5
Use `Environment.GetFolderPath(Environment.SpecialFolder.ApplicationData)` (or `LocalApplicationData` for cache-only data), then `Path.Combine` with company/app segments — never hard-code drive letters. `CurrentDirectory` follows the process working directory (IDE/shell dependent); deployed apps often resolve assets relative to `AppContext.BaseDirectory` instead.

### Question 6
Naive `Split(',')` treats commas inside quotes as delimiters, yielding too many columns. Scan character-by-character, toggling an `inQuotes` flag on `"`, doubling `""` inside quotes, and only splitting on commas outside quotes — or use a minimal quote-aware parser like the tutorial's `SplitQuotedLine`.

### Question 7
(1) Leaving a `FileStream`/`StreamWriter` open while another process deletes or replaces the file. (2) Opening the same file for exclusive write twice without sharing flags. (3) Forgetting `Dispose`/`using`, keeping a lock until GC. `using` ensures handles close; `Flush` pushes writer buffers so tail readers see data.

### Question 8
`Directory.Delete(path, recursive: false)` throws if the folder is not empty. Pass `recursive: true` to remove nested files and subfolders, or delete children first. Guard with existence checks when paths are user-supplied.

### Question 9
File-backed: `new StreamReader(filePath)` passed to the method. In-memory: `new StringReader(csvText)` — both are `TextReader` implementations, enabling the same parser logic in tests and production.

### Question 10
`FileMode.OpenOrCreate` opens existing or creates empty; `FileMode.Truncate` opens an existing file and sets length to 0 while keeping the handle — useful for rewrite-in-place without deleting the path.

### Question 11
Only `published\report.txt` exists; `Move` removes the source. On the same volume, `Move` is typically an atomic rename — faster and avoids a window where both copies exist or neither exists if copy-then-delete fails midway.

### Question 12
Use `CultureInfo.InvariantCulture` (or fixed format like `"F2"`) when writing numeric CSV fields and the same culture in `TryParse` on import — never rely on thread current culture for interchange files.

### Question 13
`Directory.EnumerateFiles(root, "*.log", SearchOption.AllDirectories)` — yields paths lazily as you iterate, avoiding allocating a huge `string[]` for very large trees.

### Question 14
`FileMode.Append` seeks to end before each write. Call `Flush` on the writer/stream (and dispose when done) before external tools read `FileInfo.Length` or tail the file, or they may see stale size/buffered content.

### Question 15
`GetFullPath` resolves relative segments against `Environment.CurrentDirectory`. For deployed apps, combine `AppContext.BaseDirectory` with the relative segment via `Path.Combine`, then optionally `GetFullPath` on that anchored path so resolution does not depend on where the shell started the process.

### Question 16
Setting `FileAttributes.ReadOnly` causes overwrite attempts to throw `UnauthorizedAccessException` (or fail on some OS APIs). Clear or restore attributes before intentional writes, or use flows that respect read-only state.

### Question 17
Increment `lineNumber` for every physical line read. Skip blanks/comments without importing. First non-comment line sets `headerConsumed` and continues. For data lines, validate column count and fields — on failure append to errors list with `lineNumber` and continue loop; on success add to items.

### Question 18
Open read-only `FileStream`, `Seek(-4, SeekOrigin.End)` to position before the last four bytes, then `Read` exactly four bytes into a buffer — no need to read from offset 0.

### Question 19
`GetTempFileName()` creates a zero-byte file immediately — convenient but you must delete it. `Combine(GetTempPath(), Guid + extension)` generates a unique name without creating the file until you write — you own creation and cleanup in both cases.

### Question 20
`ReadAllLines` loads all lines into a `string[]` at once — risky for 500 MB. `ReadLines` returns lazy `IEnumerable<string>` — preferred for large feeds. `ReadAllLines` is acceptable only when size is known small.

### Question 21
Data may remain in the `StreamWriter` internal buffer and never reach disk if neither `Flush` nor `Dispose` ran — last lines can be lost after crash.

### Question 22
Read and compare magic bytes immediately after opening the stream, before reading record counts or rows. Mismatch should throw `InvalidDataException` (or custom format exception) — fail fast before misinterpreting body bytes as records.
