## Answers

### Question 1

`List<int>` is compile-time typed: adding a string fails at compile (CS1503), not at runtime with `InvalidCastException`. Reading `list[i]` returns `int` directly — no cast/unbox. `ArrayList` stores `object`; value types box on insert and every read needs `(int)` unbox; wrong runtime type throws `InvalidCastException`. Generics eliminate boxing for `int` in `List<int>`.

### Question 2

Use `Dictionary<string, Product>` keyed by SKU (or `Dictionary<string, int>` index into a list if values repeat). Average O(1) lookup by key vs O(n) linear scan on `List<Product>`. With 50k SKUs and frequent lookups, dictionary avoids scanning the whole catalog each time.

### Question 3

Declare a generic class e.g. `WarehouseSlot<T>` with type parameter `T` for the payload field. `WarehouseSlot<string>` and `WarehouseSlot<decimal>` are **closed constructed types** — distinct types at compile time; you cannot assign one to the other. One class definition, many concrete types, compile-time safety.

### Question 4

`Queue<T>` — FIFO: `Enqueue` at back, `Dequeue` from front only. API prevents arbitrary middle removal. `List<T>` allows `RemoveAt(i)` anywhere, so fairness rules are not enforced by the type.

### Question 5

`Stack<T>` — LIFO: `Push` adds on top, `Pop` removes most recent. Matches undo semantics (last edit undone first).

### Question 6

(a) Union — all tags in A or B (`Union` / `UnionWith`). (b) Intersect — tags in both (`Intersect` / `IntersectWith`). (c) Except — tags in A not in B (`Except` / `ExceptWith`). Wrap LINQ results in `HashSet` if set semantics needed.

### Question 7

`SortedList<TKey,TValue>` or `SortedDictionary<TKey,TValue>` keep keys sorted on insert — foreach visits ascending SKU order without explicit `Sort`. Use **SortedList** when you need `Keys[i]` / `Values[i]` O(1) access by sorted rank (report row 0 = first SKU). Use **SortedDictionary** when entries churn often (tree rebalance vs array shifting).

### Question 8

Pass `IEqualityComparer<Subscriber>` to the `HashSet` constructor (e.g. compare email case-insensitive), **or** override `Equals`/`GetHashCode` (or `IEquatable<Subscriber>`) on the type using email. **Contract:** if `Equals` returns true, `GetHashCode` must match — otherwise `Contains`/`Remove` break silently.

### Question 9

`InvalidOperationException`: “Collection was modified; enumeration operation may not execute.” Safer: iterate a copy (`new List<T>(original)`), collect changes and apply after the loop, or use index-based loop if removing while iterating backward.

### Question 10

**`yield return`** in an iterator method returning `IEnumerable<T>`. Work runs lazily when consumer calls `MoveNext` (via `foreach`) — each `yield return` produces one element and pauses until the next request.

### Question 11

`IEnumerable<out T>` is **covariant** (`out`): you only read `T` out. `IEnumerable<string>` is assignable to `IEnumerable<object>` because every string is an object. `List<T>` is **invariant** — no `List<string>` to `List<object>` because `List<object>` could `.Add(any object)`.

### Question 12

Read legacy pairs, cast/unbox values to `int`, populate `Dictionary<string,int>`. Replace `Hashtable` indexer/add with `TryGetValue`/`Add`. Pitfall: `InvalidCastException` if a value was stored as wrong type; null keys throw `ArgumentNullException` on generic dictionary.

### Question 13

`HashSet<string>`: O(1) average `Contains`/`Add` (returns false if duplicate). `List<string>` duplicate check is O(n) per insert; at millions of IDs, list scanning is prohibitive. HashSet enforces uniqueness by design.

### Question 14

**SortedDictionary** — red-black tree: insert/remove O(log n) without shifting arrays. **SortedList** insert/remove shifts parallel key/value arrays — O(n). Frequent churn favors SortedDictionary.

### Question 15

One **generic method** `Swap<T>(ref T a, ref T b)` — single algorithm for all types. Compiler **infers** `T` as `string` when both arguments are strings; explicit `Swap<string>(ref a, ref b)` is equivalent.

### Question 16

`TryGetValue(sku, out Product product)` — one hash lookup; returns false if missing, no exception. Avoids double lookup of ContainsKey + indexer GET.

### Question 17

`Queue<(row,col)>` — BFS enqueues start, repeatedly `Dequeue`s current cell, enqueues unvisited neighbors. Queue preserves “expand layer by layer” (increasing distance from start) — FIFO order of discovery.

### Question 18

**IComparable** = one natural order baked into the type (`Sort()` parameterless). **IComparer** / **Comparison delegate** = external sort orders without changing the class — multiple rules (priority vs SKU). For changing sort rules, prefer IComparer or `Sort((a,b)=>…)`.

### Question 19

`internalLanes.AsReadOnly()` → `ReadOnlyCollection<T>`. View cannot Add/Remove/set indexer — `NotSupportedException`. Underlying list still mutable; changes visible through the read-only view (live wrapper).

### Question 20

Boxing wraps value type `int` in heap `object` on `ArrayList.Add(42)`. Extra allocations + GC pressure for high-frequency samples. Use `List<int>` — stores ints directly, no box/unbox.

### Question 21

`UnionWith` on the first `HashSet<string>` — adds all elements from the second set in place, no duplicates. Non-mutating alternative: `permissions.Union(draftPerms)` then wrap in new HashSet.

### Question 22

Implement **`IEnumerable<T>`** (and optionally non-generic `IEnumerable`). `GetEnumerator()` returns **`IEnumerator<T>`** with `MoveNext()` / `Current` / `Dispose` — powers `foreach` via compiler desugaring.
