## Answers

### Question 1
LINQ to Objects builds an iterator pipeline; `Where` does not scan until enumeration. Force execution with a terminal operator (`Count`, `Sum`, `ToList`, `First`, etc.) or `foreach`. Until then the query is only a recipe (ch.01 deferred execution).

### Question 2
Both loops see the updated data because deferred queries re-read the source. `ToList()` or `ToArray()` materializes a snapshot at one point in time (ch.01, ch.10).

### Question 3
Standard operators (`where`, `select`, `orderby`, `group`, `join`) translate to the same methods when keys align. Method syntax is required for overloads with no query keyword (e.g. `ThenBy`, `DistinctBy`, `SelectMany` with two lambdas, comparer parameters) (ch.01).

### Question 4
Use `OfType<ProductRow>()` — skips non-matching elements. `Cast<ProductRow>()` throws `InvalidCastException` on the first bad item (ch.02, ch.10).

### Question 5
`Average()` throws `InvalidOperationException` on empty sequence. Guard with `Any()`, check `Count() > 0`, use conditional logic, or return `null`/sentinel without calling `Average` (ch.02).

### Question 6
`Aggregate` — seeded overload `(seed, (acc, item) => …)` then optionally divide; seedless `Aggregate` throws on empty (ch.02).

### Question 7
Second `OrderBy` replaces the first sort entirely — result sorted by Priority only. Use `OrderBy(Zone).ThenBy(Priority).ThenBy(Sku)` on `IOrderedEnumerable` (ch.03).

### Question 8
Pass `IComparer<string>` to `OrderBy` that parses letter prefix and numeric suffix, or project a sort key tuple `(letter, number)` via `OrderBy` (ch.03 custom comparer).

### Question 9
`GroupBy` is deferred — recomputes when re-enumerated; good for reports. `ToLookup` executes immediately and supports `lookup[key]` with empty sequence for missing keys — better for repeated random access by assignee (ch.04, ch.10).

### Question 10
`ToDictionary` requires unique keys; duplicate carrier keys throw `ArgumentException`. Group first (`GroupBy` + sum weight) then `ToDictionary(g => g.Key, g => g.Sum(...))` (ch.04, ch.10).

### Question 11
`customers.GroupJoin(orders, c => c.Id, o => o.CustomerId, (c, orderGroup) => new { c, orderGroup })` then `from o in orderGroup.DefaultIfEmpty()` — unmatched customers get one row with `default` order fields (ch.05).

### Question 12
Query join requires `equals` for equality pattern; `==` is C# boolean operator in different context. Mismatched key types → compile error CS1943 (ch.05).

### Question 13
`First`/`FirstOrDefault` take first match; multiple pending still succeed. `Single` throws `InvalidOperationException` if zero or more than one match — enforces exactly-one rule (ch.06).

### Question 14
Without stable `OrderBy`, source order can change as data mutates — Skip/Take slices arbitrary order. Sort first (e.g. by Customer or Id) then page (ch.03, ch.11).

### Question 15
`Chunk(size)` yields `T[]` batches; last array may be shorter when length not divisible by size (ch.11).

### Question 16
`Union` with custom `IEqualityComparer<SkuEntry>` (or `UnionBy` on keys). `Concat` would keep duplicates (ch.07).

### Question 17
`All` on empty returns **true** (vacuous truth). Need `batch.Any() && batch.All(p => p.Price > 0)` so empty fails at `Any` (ch.09).

### Question 18
`SequenceEqual` — same length and pairwise equal elements; order matters. `Intersect` is set-like, ignores order and duplicates policy differs (ch.09 vs ch.07).

### Question 19
`orders.SelectMany(o => o.Lines, (o, line) => new PickRow(o.OrderId, o.Customer, line.Sku, line.Qty))` — flattens while keeping parent fields (ch.08).

### Question 20
`Range(start, count)` — second arg is **count** of elements, not end index. Use `Range(10, 5)` for 10..14 (ch.12).

### Question 21
`Enumerable.Empty<PickRow>()` — typed empty singleton sequence, safe to foreach (ch.12).

### Question 22
`Descendants("sku")` walks full subtree; returns `IEnumerable<XElement>` — use `.Where`, `.Select`, `.Average` like any LINQ source (ch.13).

### Question 23
Use `(string?)element.Attribute("active")` or `?.Value`, compare to `"true"`, or `(bool?)attr` with null check; combine `?.` on missing elements before cast (ch.13).

### Question 24
Ordering chapter notes PLINQ `AsParallel().OrderBy` may not preserve same stability/merge semantics as sequential LINQ to Objects. Full PLINQ → **06. Multithreading & Async Programming** Parallel chapter (ch.03 preview).
